# Backend Module (src-tauri)

## Responsibilities

Everything the webview cannot do: the filesystem, the pseudo-console, the tray,
theme font loading, the config and data directories, and the update download.
Built with Tauri v2 + Rust.

## Entry Points

- **Entry**: `src/main.rs` — calls `wingharness_lib::run()`
- **App Logic**: `src/lib.rs` — the plugin list, the `.setup()` hook, and
  `all_commands!`
- **Build Script**: `build.rs` — the ACL guard (see below)
- **Build Config**: `Cargo.toml`; `tauri.conf.json`, with
  `tauri.dev.conf.json` overriding the identifier for dev builds

```bash
pnpm tauri dev     # Development build
pnpm tauri build   # Production bundle
cargo check        # Called from this directory; faster for Rust-only edits
```

## The Four Lists

A command is only callable once it is named in all four of these, and only
`build.rs` cross-checks any of them:

| List | File | What it is |
|------|------|------------|
| Handler | `src/invoke.rs` | `all_commands!` — the single `generate_handler!` list |
| Guard | `build.rs` | `const COMMANDS` — mirrors the handler list |
| Capability | `capabilities/default.json` | `allow-<command>` entries granted to this app's windows |
| Permission | `permissions/autogenerated/*.toml` | One file per command, referenced by the capability |

`build.rs` fails the build when the handler list and `COMMANDS` disagree. The
other two it cannot see, so a command added to the first two and not to the last
two compiles and then fails at runtime with "not allowed by ACL".

### Adding a command

1. Write it in `src/commands/<module>.rs` with `#[tauri::command]`
2. Add it to `all_commands!` in `src/invoke.rs`
3. Add its name to `COMMANDS` in `build.rs`
4. Add `"allow-<command>"` to `capabilities/default.json`
5. Add the matching `permissions/autogenerated/<command>.toml`
6. Wrap it in `src/commands/services/<domain>/` and re-export from
   `src/commands/index.ts` — see [../src/CLAUDE.md](../src/CLAUDE.md)

Why the ACL matters here: without an application manifest of its own, Tauri
checks access control only for plugin commands, so *every* application command
becomes callable from *any* webview. With the manifest in place the capability
grants these permissions to `main`, `about`, `settings` and `tray-menu` only, and
the caller's origin additionally has to match.

## Config and Data Directory

- `src/config/mod.rs` is deliberately plain `std` + `serde_json`, with no Tauri
  handle, so it stays usable from tests and tools
- `config.json` holds `workspace.root` — the project the file browser and the
  preview open at. An empty root is a valid state: the pages show an empty state,
  not an error
- `data-dir.txt` is a pointer file in the *default* config directory naming the
  directory actually in use. It lives there on purpose: it has to be found before
  the app knows where anything else is
- `config::dir()` is where every piece of persisted state goes — notes, cached
  fonts, config. It is resolved once at startup, so changing it takes effect after
  a restart
- `config::init(dir)` is called from `.setup()`; the preview crate gets the project
  root through `provide_root()`, which resolves per call so a settings change
  needs no restart

## Crates

`file-preview/` is a workspace member: the preview page's byte reader, kept
separate so it can be tested and reasoned about without Tauri. It exposes exactly
two commands, resolves its root through the provider the app installs, and is the
only backend work the preview page does. See
[../docs/FILE_PREVIEW.md](../docs/FILE_PREVIEW.md).

`plugins/` is the app's own tray — the native icon and, on Windows, its themed
right-click menu. Not to be confused with Tauri plugins (the `tauri-plugin-*`
crates), which are Rust dependencies.

## Windows

`tauri.conf.json` declares `main` and the hidden `tray-menu` popup. The `about`
and `settings` windows are created on demand by the frontend
(`createWindow()` in `src/lib/window.ts`), which is why they do not appear there.
All four labels are listed in `capabilities/default.json`.

## Key Dependencies

| Crate | Purpose |
|-------|---------|
| `tauri` | Framework core (tray-icon feature) |
| `tauri-plugin-opener` | Open external links |
| `tauri-plugin-dialog` | Folder picker for the data directory |
| `tauri-plugin-global-shortcut` | OS-level shortcuts |
| `tauri-plugin-single-instance` | Focus the running window instead of starting a second copy |
| `tauri-plugin-window-state` | Restore window geometry (`tray-menu` denied) |
| `tauri-plugin-process` / `tauri-plugin-updater` | Update install and restart |
| `portable-pty` | The terminal's pseudo-console |
| `font-kit` / `fontdb` | Load a chosen family; enumerate the installed ones |
| `reqwest` | Update check and web font download |
| `serde` / `serde_json` | Serialization (`preserve_order` keeps `config.json` stable) |
| `tokio` / `futures-util` | The update download's runtime and stream combinators |

`tauri-plugin-updater` is only registered in release builds; the updater commands
cover the download side, which both builds need.

## File Structure

```
src-tauri/
├── Cargo.toml              # Dependencies; [workspace] members = ["file-preview"]
├── build.rs                # ACL guard: COMMANDS vs capabilities/default.json
├── tauri.conf.json         # Windows, bundle, updater endpoint placeholders
├── tauri.dev.conf.json     # Dev-build identifier override
├── capabilities/
│   └── default.json        # Permissions, granted to the four window labels
├── permissions/
│   └── autogenerated/      # One allow-<command>.toml per command
├── file-preview/           # Workspace crate: the preview page's backend
├── icons/
└── src/
    ├── main.rs             # Entry point
    ├── lib.rs              # Plugins, setup hook, all_commands!
    ├── invoke.rs           # The handler list
    ├── commands/           # One module per command domain + fs_guard.rs
    ├── config/             # config.json, the data-directory pointer, config::dir()
    ├── fonts/              # Installed font enumeration
    ├── plugins/            # The app's tray: system_tray, tray_popup (Windows)
    └── theme/              # Theme preset web fonts
```

## Code Quality

- Follow Rust naming conventions
- **Comments, console logs and error strings MUST be in English only**
- User-facing messages the frontend renders are returned as English strings and
  translated in the frontend; do not return localized text from Rust
