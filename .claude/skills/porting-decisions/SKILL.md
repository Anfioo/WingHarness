# 移植可行性 · 决策清单

把一个源项目搬进来之前，把「会分叉的路口」问清楚，写成一份计划可引用的决策文件。

## 产出

```
.dev/Plans/<module>/decisions.md          # 相对仓库根
```

- `<module>` 与后续 `porting-plan-waves` 用同一个名字。
- 文件已存在时进入**续问模式**：保留已答条目，只补未决项，不重写历史结论。
- 产物只有这一个文件。不写 `plan.1.md`、不改代码、不动仓库。

## 路径约定

- 仓库内的路径（源码、`.dev/Plans/`、`.dev/Projects/`）一律写**相对仓库根**，不带盘符。
- 只有仓库外的源项目才写绝对路径（用户给的是 `D:\...` 这类路径时按其原值引用）。
- 命令在仓库根执行，不出现 `cd M:\...`。
- 文件里出现的每条「依据」都要能被窗口按同一基准复现，所以不要混用两种基准。

## 何时用 / 不用

- **用**：移植 / 迁移前方案未定；已有计划但 §0 的范围与形态没确认；用户问「这个能搬进来吗」「有哪些坑」。
- **不用**：方案已定，只要施工图 → 直接 `porting-plan-waves`；只改一个小文件 → 不需要决策文件。

## 工作流

### 1. 定位两端

| 项 | 处理 |
|----|------|
| 源项目 | 绝对路径 → 只读校验（在仓库内则改写成相对路径）；git URL → clone 到 `.dev/Projects/<name>`（已存在则复用），之后用相对路径引用 |
| 目标仓 | 仓库根，只读；不构建、不修改 |
| 模块名 | 从源项目名取 kebab-case；用户给了就用用户的 |
| 已有决策文件 | 先读，按 `## 3 决策记录` 的 Q 编号续接 |

### 2. 先查再问（硬规则）

**代码里能查到的，不许拿去问用户。** 按 [question-bank.md](question-bank.md) 的 16 类逐类过一遍，每类先取证：

- 依赖与版本：`package.json`、`src-tauri/Cargo.toml`、`Cargo.lock`、`pnpm-lock.yaml`
- 布局：源的导航/侧栏/窗口结构 vs 本仓 `src/components/app-shell.tsx`、`app-sidebar.tsx`
- 存储：源用 SQLite / localStorage / keyring / 文件；本仓 `src-tauri/src/config/mod.rs`
- 外部运行时：源是否依赖二进制、系统命令、端口
- 许可：两端 `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`
- 可复用：本仓已有的编辑器、预览器、虚拟列表、格式化函数

每一条写进 `## 1 已核实的事实`，带 `路径:行号` 或文件行数。查不到就写「待核实」，不要猜。

### 3. 先写初稿，再提问

提问之前先把 `decisions.md` 写到「冲突清单 + 待决问题」为止（用 [decisions-template.md](decisions-template.md)）。这样用户中途停下也有产物。

冲突清单的「处理」只允许四种：`按本仓重写`、`保留源实现`、`丢弃`、`待定`。

### 4. 分批提问

- 用 `AskUserQuestion`，**每批最多 4 个问题**（工具上限），每题 2–4 个选项。
- **只问真分叉**：会影响交付形态、范围、数据、安全、许可、依赖体积的。工程细节（原子写、错误码形状、测试策略、命名）直接落「计划默认」。
- 第一个选项是推荐项，标签末尾标 `(推荐)`；每个选项的描述写清**代价与后果**，而不是复述选项名。
- 排序：阻塞 A0 的 → 影响范围/工作量的 → 其余。
- 每批答完**立即回写** `decisions.md`（结论、来源、日期、落到 plan 的哪一节），再开下一批。
- 用户说「剩下的你定」→ 推荐项落为「计划默认」，写进 `## 4 默认假设`，不再追问。
- 问题总数控制在 **12–16 条**；超过说明该拆成两个模块分别规划。

### 5. 收尾

补齐 `## 5 开放问题` 与 `## 6 给 porting-plan-waves 的输入摘要`，然后只回报：

- 文件路径
- 已定 N 条 / 仍开放 M 条
- 对计划的三个最大影响（范围、工作量、风险）

## 决策条目的写法

每条必须四段齐全，缺一段就是没做完：

```markdown
### Q3 源项目的固定左栏要不要保留？

- 问题：源的导航是左侧固定栏 + 主区；本仓是 `SidebarProvider` + 左侧可折叠 `AppSidebar` + 页头。
- 事实：源 `src/index.html:266` 起为 240px 固定栏；本仓 `src/components/app-shell.tsx:148-186`。
- 选项：
  - A（推荐）：只保留信息架构，套进本仓侧栏 + 页内二级导航；代价是源的多面板布局要重排。
  - B：页面内自绘三栏，复刻源布局；代价是与全局侧栏双层导航并存，视觉更重。
  - C：改成独立窗口，一实例一工作区；代价是新增窗口注册与能力清单。
- 结论：A
- 来源：用户确认（2026-11-06）
- 落到：plan §7.1 / §7.2
```

## 必须问 vs 计划默认

| 必须问用户 | 直接落计划默认 |
|------------|----------------|
| 功能范围裁剪（哪些不做） | JSON 原子写、损坏备份 |
| 交付形态（单页 / 多标签 / 独立窗口） | 错误码用 `{ code, message, detail }` |
| 旧数据是否迁移 | Rust 单测覆盖策略 |
| 凭据存放（明文 / 不存） | 命令前缀、crate 名、i18n 命名空间 |
| 许可不兼容时的取舍（换实现 / 放弃） | 文档双语、NOTICE 格式 |
| 重大新增依赖（体积、运行时） | 文件所有权与波次划分 |

## 常见冲突（逐类过，不许漏）

1. **框架版本冲突**：源 CM5 / React 17 / Tauri v1 / rusqlite → 本仓 CM6 / React 19 / Tauri v2 / sqlx。默认「按本仓重写适配层」，不要为兼容旧版并行装两套。
2. **UI 体系冲突**：源原生 CSS 或别的组件库 → Tailwind v4 + shadcn/ui。默认「参考交互重写」，不搬样式。
3. **信息架构冲突**：源固定左栏 / 顶部导航 / 多面板 → 本仓左侧可折叠栏 + 页头。默认「保留信息架构，套本仓外壳」。
4. **窗口模型冲突**：源多窗口 / 一窗口一文档 → 本仓单页 + 标签，或一实例一窗口。**必须问**。
5. **范围冲突**：源 10+ 模块 → 本期只做一部分。**必须问**。
6. **存储冲突**：SQLite / localStorage / keyring → `config::dir()` 下 JSON。默认 JSON；**旧数据是否迁移必须问**。
7. **平台冲突**：源支持 macOS/Linux → 本仓只验收 Windows。默认「代码跨平台、只 Windows 验收」。
8. **外部运行时**：需要 `git`/`svn`/`frpc`/浏览器等二进制。默认「探测本机、不内置下载」；是否需要投递安装包要问。
9. **许可冲突**：无许可证，或被准入表拒绝的许可证（如没有 Secondary License 声明的 EPL-2.0）→ 不可移植；AGPL / GPL-3.0 / MIT / BSD / ISC / Apache-2.0 / MPL / LGPL → 可，但要补归属。**不兼容时必须问**。
10. **复用冲突**：本仓已有渲染器、编辑器、预览器。默认「先复用，缺能力再新增」。
11. **快捷键/右键冲突**：源的全局快捷键与本仓 `lib/shortcut.ts` 注册冲突。默认页面内处理，不注册系统级。
12. **命名冲突**：命令前缀、route id、i18n 命名空间、crate 名与现有 11 个 `-core` 撞车。默认加模块前缀。
13. **依赖体积**：新增 npm 包 / Rust crate。默认能不装就不装；>500KB 或引入原生库时问。
14. **测试差异**：源无测试 / 用 Jest → 本仓只做 Rust 单测 + 前端纯函数。默认按本仓。
15. **文档与归属**：源文档缺失。默认补双语功能文档 + `UPSTREAM.md` + `THIRD_PARTY_NOTICES.md`。
16. **更新与发布**：源自带自动更新 / 托盘。默认不移植，本仓已有自己的更新链。

## 与 porting-plan-waves 的衔接

- 计划技能会先读 `decisions.md`：`## 3 决策记录` → plan §0 / §10；`## 1 事实` → plan §2 的复核起点（仍要实测）；`## 5 开放问题` → 计划的「开工前检查」。计划生成的 `prompts.md` 还会为每个施工波次生成收尾协调者提示词，用于处理该波次各轨的 `## 待协调`，不负责派发执行 Agent。
- 用户的使用话术：**「用 porting-plan-waves，决策见 `.dev/Plans/<module>/decisions.md`」**。
- 已答的 Q 不得在计划阶段重复问；计划阶段只允许新增「出现了决策文件没覆盖的新问题」。

## 质量自检

- [ ] 每个问题都有事实依据，且代码里查不到答案。
- [ ] 每条决策四段齐全（问题 / 事实 / 选项与代价 / 结论 + 来源 + 落点）。
- [ ] 「必须问」的六类都问过或已明示跳过。
- [ ] 每批 ≤4 题，答完即回写文件。
- [ ] 默认假设单独成表，没混进「用户确认」。
- [ ] §6 的输入摘要能被计划技能直接引用，不需要再读全文。
