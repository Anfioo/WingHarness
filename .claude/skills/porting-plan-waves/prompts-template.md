# inbox/prompts.md 骨架

一份文件里放原有执行提示词和波次收尾协调提示词：先给波次表与「所有窗口都必须知道的四件事」，然后按波次排列。提示词块用 `~~~` 围栏——正文里会出现代码块，用 ``` 会提前截断。

````markdown
# <模块名>并行开发 —— 执行与波次协调提示词

本文保留 A0、B/F、A1 的执行提示词；每个施工波次结束后追加一段协调者提示词。用户先手动开启 A0 或各轨执行提示词；该波次全部执行轨完成后，再手动开启对应的「波次收尾协调者」提示词。协调者不派发 Agent，不替代执行轨，只处理上一波的 `## 待协调` 并把当前工作区推进到可以开启下一波的程度。

## 波次与窗口分配

| 波次 | 可同时开的窗口 | 说明 |
|------|----------------|------|
| W0 | A0 | 必须先完成并合入，后面所有轨都依赖它冻结的接口 |
| W1 | B1、B2、F1 | 三轨文件互不重叠，可完全并行 |
| W1 结束协调 | W1-C | 处理 W1 各轨「待协调」，通过门禁后才可开启 W2 |
| W2 | B3、F2 | 两轨文件互不重叠 |
| W2 结束协调 | W2-C | 处理 W2 各轨「待协调」，通过门禁后才可开启 A1 |
| W3 | A1 | 联调、补测、i18n、文档 |

### 每个波次协调者的职责边界

- 只在该波次所有执行轨完成后运行；不得提前为未完成的轨道补业务实现。
- 读取上一波所有执行轨工作单末尾的 `## 待协调`、完成回报和提交状态。
- 按优先级处理会阻塞下一波的命令、DTO、事件、公开签名、i18n 与共享文件变更；必要时只修改计划规定的共享文件。
- 不负责派发执行 Agent，不修改其他轨的独占业务文件，不替执行轨完成未完成的功能。
- 处理后运行本波次门禁；失败时修复协调层问题或停止并报告阻塞，不得假装放行。
- 只有当待协调项已处理或明确记录为不阻塞、共享接口已冻结、工作区可编译且下一波前置条件满足时，才报告“可以开启下一波”。


1. **工作目录是仓库根（WingHarness 仓库根目录）**，仓库只有这一个工作树；提示词里的路径都相对它，不要另建 worktree。
2. **分支 `feature/<module>` 由协调者建好**。不要切分支、不要建分支、不要合并。
3. 所有窗口共用一个 `target/`。并发 `cargo check` 会在 target 锁上短暂排队，属正常现象，不要改构建配置或中断。
4. 详细清单在 `.dev/Plans/<module>/inbox/<lane>.md`，计划在 `plan.1.md`；`.dev/` 不是 Git 仓库。

- 不要跑 `pnpm format` 或仓库级格式化；不要动无关文件；不要 `git add -A` 或 `git add .`，只按明确路径 add。
- 不要启动 `pnpm tauri dev`。

完成后回报：改了哪些文件、两个提交的 hash、与 A0.md 的偏差、以及需要 W1 各轨知道的入口与注意事项。不要顺手实现 B/F 轨的业务逻辑。

## W1-C —— W1 波次收尾协调者

~~~
你在 WingHarness 仓库根目录工作（下文路径均相对仓库根）。W1 的 A0 基线及 B/F 执行轨已经完成。本任务不是派发 Agent，也不是替任何执行轨补业务功能；只处理 W1 各轨留下的「待协调」，把当前工作区推进到可以开启 W2 的程度。

必读（按顺序）：
1. .dev/Plans/<module>/plan.1.md —— 重点 §6、§8、§11、§13
2. .dev/Plans/<module>/inbox/A0.md —— 冻结接口与共享文件所有权
3. .dev/Plans/<module>/inbox/B1.md、B2.md、F1.md —— 各轨「待协调」与完成记录（按实际波次替换）
4. 其他本波次执行轨工作单及其完成回报

前置检查（硬性）：
- 执行 `git rev-parse --abbrev-ref HEAD` 与 `git status --porcelain`。
- 确认本波次所有执行轨均已完成并有提交 hash；缺任何一轨就停止并报告，不要替它实现功能。
- 确认没有与本次协调无关的未提交改动；不要 stash、reset、clean 或切换分支。

协调范围：
1. 汇总并逐条处理上一波各轨 `## 待协调`：命令、DTO、事件、公开签名、i18n、共享类型和文档登记项按计划归属处理。
2. 只修改计划 §11.2 规定的共享文件，以及必要的本波次协调记录；不得修改 B/F 轨独占业务文件来掩盖未完成工作。
3. 对不阻塞下一波的事项明确记录为「延后至 A1」或「不阻塞」，并保留原因；不能静默删除。
4. 检查接口冻结、文件所有权、提交状态和下一波工作单的前置依赖。

验收：
  cd src-tauri; cargo check -p <module>-core; cargo test -p <module>-core
  cd ..; pnpm build; pnpm exec eslint <本功能文件>

完成标准：
- 上一波所有「待协调」已处理，或逐项标明不阻塞及后续归属。
- 共享接口、命令登记、DTO、事件与 i18n 已达到 W2 可直接使用的状态。
- 门禁全绿，或明确报告阻塞项；只有全绿且前置条件满足时才报告「可以开启 W2」。

完成后回报：处理了哪些待协调项、修改了哪些共享文件、验收结果、剩余风险，以及 W2 是否可以开启。不要派发 Agent，不要实现 B/F 轨遗漏的业务逻辑。
~~~

## B / F 轨提示词的 12 项自检

每段提示词复制出去就能开工，缺一项都不合格：

1. 工作目录与分支
2. 开工前 `git status` 检查 + 不符时停下报告
3. 独占文件清单
4. 只读/禁止修改清单
5. 必读文档的路径（仓内相对、仓外绝对）
6. 冻结的接口签名
7. 分步实施步骤
8. 验收命令
9. 提交格式与 `git add` 纪律
10. 改共享文件的做法（写「待协调」）
11. 并发构建说明（共用 target、cargo 排队正常）
12. 完成标准与回报内容
````
