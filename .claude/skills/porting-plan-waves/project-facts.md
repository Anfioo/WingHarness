# WingHarness 事实清单

生成计划时直接引用这里的事实，不必重新推导；但**目录结构会演进**，每个计划开工前仍要复核一次本文件列出的路径是否存在。

## 仓库

| 项 | 值 |
|----|----|
| 根目录 | 仓库根（下文所有路径都相对它；含 `.dev/` 下的计划与参考工程） |
| 许可证 | AGPL-3.0-only |
| 前端 | React 19 + TypeScript strict + Vite 7 + Tailwind v4 + shadcn/ui |
| 后端 | Tauri v2 + Rust |
| 包管理 | pnpm；`pnpm tauri dev`（dev 端口 11421） |
| 平台 | Windows 11 + PowerShell |
| 参考工程缓存 | `.dev/Projects/<name>`（新增源的放这里） |
| 计划产出 | `.dev/Plans/<module>/` |

路径只有两种写法：仓库内的写相对仓库根（`src/main.tsx`、`.dev/Projects/<name>/...`），仓库外的源项目才写绝对路径。命令一律在仓库根执行。

## 后端 crate 约定

功能后端一律独立 crate，放在 `src-tauri/<module>-core/`：

- 登记两处：`src-tauri/Cargo.toml` 的 `[workspace] members` 与 `[dependencies]` 里的 `path` 项。
- 现有成员（`src-tauri/Cargo.toml`）：`file-preview-core`、`git-core`、`api-core`、`svn-core`、`shaic-core`、`prism-core`、`systools-core`、`server-core`、`frp-core`、`md-editor-core`、`db-core`。新 crate 名字不得重复。
- crate 内常见结构：`lib.rs`、`error.rs`、`paths.rs`、`models.rs`、`store.rs`、`commands.rs` + `commands/<域>.rs`。别为小功能提前拆模块。
- 持久化：只写 `config::dir()/<module>/`（`src-tauri/src/config/mod.rs`）。JSON 原子写 = 同目录 `.tmp` → `sync_all` → `fs::rename`；损坏文件备份为 `.bak-<unix秒>` 后回落默认值。**禁止 localStorage**。
- 状态注入：`src-tauri/src/lib.rs` 的 `.setup()` 里 `CONFIG_DIR.set(config::dir().join("<module>"))` + `app.manage(...)`；需要清理子进程时挂 `RunEvent::Exit`。

## 命令注册（四张表）

| 表 | 文件 | 说明 |
|----|------|------|
| Handler | `src-tauri/src/invoke.rs` | `all_commands!` 里的 `generate_handler!` 列表 |
| Guard | `src-tauri/build.rs` | `const COMMANDS`，**字母序**；与前表不一致直接构建失败 |
| Capability | `src-tauri/capabilities/default.json` | `allow-<command>`（kebab-case）；窗口标签也在 `windows` |
| Permission | `src-tauri/permissions/autogenerated/*.toml` | 构建生成，一条命令一个文件；按显式路径提交 |

新增窗口时三处：`src/main.tsx` 的 `standalonePaths`、`tauri.conf.json` 的 `app.windows`（仅静态窗口）、`capabilities/default.json` 的 `windows`。

## 前端挂载

| 要改的 | 文件 | 具体 |
|--------|------|------|
| 路由 id / 分组 | `src/lib/app-routes.ts` | `AppRouteGroup`、`AppRouteId` 各加一项；`appRoutes` 增加 `{ id, group, path, title, navLabel, description, icon, scope, items }` |
| 侧栏分组名 | `src/lib/sidebar-config.ts` | `DEFAULT_GROUP_NAMES` 补该 group（类型完整性）；**不加进 `GROUP_ORDER`**，入口自动落入「其他」 |
| 页面 | `src/main.tsx` | `pageMap` 加 `"/<path>": lazy(() => import("./pages/<module>/index"))` |
| 页面组件 | `src/pages/<module>/index.tsx` | 默认导出，内层包 `<AppShell>` |

注意：`appRoutes` 里的 `title / navLabel / description / scope / items` 是**中文字面值**；侧栏与页头直接读它们。本仓 `en.json` / `zh.json` 里没有 `routes.*` 键块（旧文档 [src/CLAUDE.md] 的这条说法已过时，实测为准）。

窗口类功能（页 + 一窗口一实例）另有 `src/lib/<module>-windows.ts`，可参照 `git-windows.ts` / `svn-windows.ts` / `api-windows.ts`。

## i18n

两种落点，**一个功能只选一种**：

1. 命名空间目录（新功能优先）：`src/i18n/locales/<ns>/{en,zh}.ts`，并在 `src/i18n/index.ts` 的 `resources.{en,zh}.translation` 里注册 `...`。现有：`git-repo`、`api-client`、`svn-workspace`、`clash`、`systools`、`md-editor`。
2. 公共大文件：`src/i18n/locales/{en,zh}.json`。仅当新文案很少且属于全局壳层时使用。

硬规则：en/zh 逐键一致；没有 caller 的键删掉；组件里不硬编码用户可见文案。

## 前端命令封装

- 一个域一个目录：`src/commands/services/<domain>/index.ts`（函数）+ `types.ts`（DTO）。
- `src/commands/index.ts` 统一再导出；组件只从 `@/commands` 取，不直接 `invoke`。
- 命名冲突时加模块前缀导出（例如 `FrpLogEntry`），不要覆盖既有类型。

## 文档与许可

- 功能文档成对：`docs/features/<NAME>.md` + `docs/features/<NAME>.zh-CN.md`，并在 `README.md` 与 `README.zh-CN.md` 的表格加行。
- 上游记录：`docs/UPSTREAM_PROJECTS.md` + `.zh-CN.md`；整子系统移植加目录级 `UPSTREAM.md`；`THIRD_PARTY_NOTICES.md` 同步更新。
- 许可门（AGPL-3.0-only）：AGPL / GPL-3.0 / MIT / BSD / ISC / Apache-2.0 / MPL / LGPL 可移植；无许可证与 gate 拒绝的许可证不可。移植文件保留署名头。
- 功能文档不得命名为 `CLAUDE.md`（Claude Code 会把它当指令加载）。

## 质量门

| 命令 | 范围 |
|------|------|
| `pnpm build` | `tsc && vite build`——单轨门禁 |
| `pnpm exec eslint <paths>` | 只查本轨文件 |
| `pnpm exec prettier --check <paths>` | 只查本轨文件 |
| `pnpm check` | 全仓 `format:check + lint + build`；会因存量文件失败，**不作为单轨门禁** |
| `cargo check -p <module>-core` / `cargo test -p <module>-core` | 后端单轨门禁 |

- 不跑全仓 `pnpm format`；只格式化本轨新建/独占文件。
- husky：pre-commit 对暂存 `src/**` 跑 prettier + eslint --fix；commit-msg 跑 commitlint。

## 提交

```
<type>(<scope>): <中文摘要，不超过 50 字>

- <要点一>
- <要点二>
```

- `type` 只允许：`feat` / `fix` / `docs` / `style` / `refactor` / `perf` / `test` / `build` / `ci` / `chore` / `revert`（`commitlint.config.js`）。
- `subject-max-length` = 100；`subject-case` 关闭；body 前必须有空行。
- 只 `git add <明确路径>`；禁止 `git add -A` / `git add .` / `--no-verify` / `amend` / `force push`。

## 分支与并发

- 协调者开工前从 `main` 建 `feature/<module>` 并切换；此后所有轨不做分支操作。
- 同一工作树、同一分支、同一个 `target/`；不建 worktree（除非用户明确要求）。
- 同时只跑一个 cargo 构建；不并发 `pnpm tauri dev`（端口与 target 锁冲突）。
- 磁盘不足：在 `src-tauri` 下 `cargo clean` 后重试，不要中断询问。
- `src-tauri/Cargo.toml` 与 `permissions/autogenerated/*` 会出现 CRLF-only 差异：只提交显式新增命令对应的文件。

## 容易踩的坑

1. **侧栏分组**：把 group 加进 `GROUP_ORDER` 会改写现有 `sidebar.json` 布局；正确做法是只加 `DEFAULT_GROUP_NAMES`，让它落到「其他」。
2. **路由文案**：路由的中文字面值在 `app-routes.ts`，不是 i18n；改入口名要改的地方和别的页面不同。
3. **命令四处登记**：漏 `permissions/autogenerated` 或 `capabilities` 时编译通过、运行时被 ACL 拒绝。
4. **`pnpm check` 会查全仓格式**：只做单轨门禁时用 `pnpm build` + 定向 eslint/prettier。
5. **`.dev/` 不是 Git 仓库**：参考工程与计划都不提交；不要把源项目当工作树构建。
6. **同名概念**：`git-core` 是实现 Git 的 crate，`src/features/git/` 是页面侧代码；`file-preview-core` 是 crate，`src/lib/preview/` 是查看器。写文件所有权时写相对仓库根的完整路径。
7. **页面必须包 `<AppShell>`**：主窗口页面缺它会丢侧栏与快捷键；独立窗口才走自己的 frame。
8. **共享文件只归 A0**：多轨同时改 `main.tsx` / `app-routes.ts` / `i18n` 是最常见的冲突来源。
