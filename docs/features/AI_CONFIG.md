# AI Config Sync

The **AI 配置同步** (AI config sync) page is under construction. The sidebar
entry and the `/ai-config` route stay in place, but the page renders only an
"Under construction" notice while the engine is rebuilt.

## Current state

The engine lives in [`src-tauri/agent-sync-core`](../../src-tauri/agent-sync-core).
It is a plain workspace member:

- no Tauri commands, so it is absent from `invoke.rs`, `build.rs`,
  `capabilities/default.json` and `permissions/autogenerated/`;
- no other crate depends on it — the root `Cargo.toml` does not list it as a
  dependency;
- the frontend has no command wrappers and never calls it.

It still compiles and its own test suite still runs:

```bash
cargo check --workspace
cargo test -p agent-sync-core
```

## Configuration

`config.json` no longer has an `aiConfig` field. The struct keeps `serde(default)`
without `deny_unknown_fields`, so an older file that still carries the
`aiConfig` key loads normally and the key is ignored. A regression test covers
that case.

## Origin

The crate derives from the `core/` crate of
[shaic](https://github.com/dariocurr/shaic) v0.3.0 (MIT). Its store / adapter /
materialise logic is kept unchanged for now; only the app-side integration was
removed. The MIT notice and the upstream license text are retained, and the
porting record is in `agent-sync-core/UPSTREAM.md`.

## Direction

The module will come back as a skill-first asset repository: skills are the
primary managed asset, and the store and adapters are expected to be trimmed and
reshaped around that model before the page returns. Until then, do not add
commands, permissions or frontend wrappers for this crate — the next step starts
from the engine itself.
