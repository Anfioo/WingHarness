# 端口管理

**端口**页面列出本机所有正在监听的 TCP 端口，把一组常用的开发端口固定在列表顶部，并可以结束占用端口的进程。其他端口既可以按端口号平铺，也可以按应用分组。它位于侧栏的**其他**分组，只有一个页面，不单独开窗口；设置放在设置窗口的**端口**分区里。

引擎是 [`src-tauri/ports-core`](../../src-tauri/ports-core)（crate 名 `ports-core`，库名 `ports_core`），移植自 [Porter](https://github.com/t21dev/porter-app)（MIT）；移植了哪些、去掉了哪些，见 [ports-core/UPSTREAM.md](../../src-tauri/ports-core/UPSTREAM.md)。

## 界面

- **统计** — `free`、`occupied`、`system` 三个计数，统计的是当前可见的行，而不是整张表。
- **工具条** — 搜索、**按端口 / 按应用**分组切换、三个状态筛选、手动刷新，以及“最后更新”或“**已暂停**”提示。`/` 聚焦搜索框，`Escape` 清空。
- **列表** — 固定端口段始终显示，其他端口收在一个可以展开的标题按钮后面。切到**按应用**时，该段按进程名渲染成可折叠的分组：成员多的排前面，其次按名称排序，解析不出进程的行归入最后的**无进程**组。开启“仅显示固定端口”时，其他端口段完全不渲染。
- **详情抽屉** — 点行打开，按需调用 `ports_detail`；抽屉已关闭或已切换到另一个端口后才返回的响应会被丢弃。
- **设置** — 页面本身不再有自己的设置。固定端口、恢复默认与“仅显示固定端口”都在设置窗口的**端口**分区里；两个窗口共用 `settings.json`，并通过 `ports-settings-changed` 事件互相通知。

## 扫描

在 Windows 上，监听表来自 IPHLPAPI 的 `GetExtendedTcpTable`，表类型 `TCP_TABLE_OWNER_PID_LISTENER`，`AF_INET` 与 `AF_INET6` 各读一次。表在“查大小”和“读取”之间增长时（`ERROR_INSUFFICIENT_BUFFER`），最多重试四次。

```
ports_list
  → read_listeners（IPv4 + IPv6 的监听行）
      按端口去重，先出现的一行胜出，升序
  → process_names：只刷新持有端口的 PID，不刷新整张进程表
  → Vec<PortEntry>
```

**每个端口一行。** 同一个端口同时绑定在 `0.0.0.0` 和 `::` 上时合并为一行，显示的是表里先返回的那个地址。

**三种状态**，由 `status_for` 决定：

| 条件 | 状态 |
| --- | --- |
| 还没有解析出持有进程 | `free` |
| 持有进程的 PID 小于 1 000 | `system` |
| 其余 | `occupied` |

PID 阈值（`SYSTEM_PID_LIMIT = 1000`）是 Windows 上判断系统服务的经验值，不是权限检查。固定的端口若无人监听，`ports_pinned_scan` 会返回 `free` 占位行，没有地址也没有进程，这样服务还没启动时也能先把端口显示出来。

`ports_detail` 读一次监听表，找到该端口，然后只刷新那一个 PID 的可执行文件路径、命令行、工作目录、内存、启动时间和用户。sysinfo 取不到的字段保持 `null`，抽屉里显示**未知**。

## 轮询

| 循环 | 间隔 |
| --- | --- |
| 全部监听端口（`ports_list`） | 3 000 ms |
| 固定端口（`ports_pinned_scan`） | 2 000 ms |

只要满足任一条就暂停轮询：页面不活跃（`usePageActive()`）、文档隐藏、窗口最小化。暂停时 effect 直接返回，因此恢复后的第一次刷新是立即发生的，不用等下一个 tick。固定端口列表变化会通过 `pinnedKey` 重启两个循环。`ports_list` 成功会清掉错误行；固定端口扫描失败会在下一个 tick 再次设置它。

## 筛选与计数

搜索按子串匹配端口号，非空闲行还会匹配进程名，不区分大小写，并会去掉首尾空白。三个状态开关与它叠加，而且同时作用于固定端口列表和其他端口列表——三个状态全部关掉时，固定端口也会一起隐藏。

`counts` 由 `[...pinned, ...others]` 计算，因此始终描述屏幕上的内容。分组只改变其他端口列表的排列：固定端口段始终平铺并置顶。搜索生效时，页面切换为单个合并结果列表，按端口去重并升序，此时分组同样不生效。分组方式会随其他设置一起持久化，重新打开页面时保持上次的选择。

## 结束进程

```
ports_kill { pid }
  ensure_killable
  → sysinfo process.kill()
  → 轮询退出，每 50 ms 一次，总共 500 ms
  → Ok | access_denied | not_found | invalid_input | internal
```

`ensure_killable` 按以下顺序拒绝：PID 0、本应用自己的进程、小于 1 000 的 PID、不持有监听端口的 PID、以及已经不存在的 PID。正是“必须持有监听端口”这一条，让这个命令不会变成通用的杀进程接口。这些拒绝都不会走到提权路径。

界面上的结果：

- `ports_kill` 返回 `access_denied` 时，用同一个 PID 再调一次 `ports_kill_elevated`。
- 提权调用通过 `ShellExecuteExW` 加 `runas` 谓词、隐藏窗口地运行 `%SystemRoot%\System32\taskkill.exe /PID <pid> /F`，只弹一次 UAC。它最多等子进程 15 秒，退出码 0 视为成功，128 为 `not_found`，其余为 `elevation_failed`，并在 `detail.exitCode` 中带上退出码。
- UAC 被取消是 `elevation_cancelled`；页面弹一条信息提示，进程原样保留。
- 无论走哪条路径，结束后都会刷新两个列表。

所有命令字符串都在 crate 内部拼装，前端只传 PID。

## 命令

| 命令 | 参数 | 返回 |
| --- | --- | --- |
| `ports_settings_get` | — | `PortsSettings` |
| `ports_settings_set` | `{ settings }` | 实际写入的规范化设置 |
| `ports_list` | — | `PortEntry[]` |
| `ports_pinned_scan` | `{ ports }` | `PortEntry[]`，包含空闲占位行 |
| `ports_detail` | `{ port }` | `PortDetail \| null` |
| `ports_kill` | `{ pid }` | `void` |
| `ports_kill_elevated` | `{ pid }` | `void` |

一个命令只有在四张表里都出现才可调用：`src/invoke.rs` 的 `all_commands!`、`build.rs` 的 `COMMANDS`、`capabilities/default.json`，以及 `permissions/autogenerated/*.toml`。

错误形如 `{ code, message, detail }`，`message` 是供日志使用的英文，前端按 `code` 翻译：

| 代码 | 含义 |
| --- | --- |
| `not-found` | 进程或端口已经不存在 |
| `invalid-input` | 页面不应操作的 PID 或端口，`detail.field` 指明字段 |
| `access-denied` | Windows 拒绝了普通结束操作——应走提权路径 |
| `elevation-cancelled` | UAC 提示被取消 |
| `elevation-failed` | 提权的 `taskkill` 失败、超时，或返回了其他退出码 |
| `not-implemented` | 预留，目前没有命令返回它 |
| `internal` | 读或写没能完成 |

## 数据与存储

```
<data dir>/ports/
└── settings.json
```

```json
{
  "version": 1,
  "pinnedPorts": [3000, 5173, 8080, 5432, 27017],
  "pinnedOnly": false,
  "groupBy": "port"
}
```

`version` 为将来的迁移而写，读取时忽略。`groupBy` 取 `"port"` 或 `"app"`；早于该字段写出的文件会按 `"port"` 读入。目录来自 `ports_core::paths::CONFIG_DIR`，在 `src-tauri/src/lib.rs` 中一次性设置为 `config::dir().join("ports")`，所以文件会跟着配置的数据目录走。

- **文件不存在** — 返回五个默认端口，且不写盘。全新安装会一直保持干净，直到用户保存。
- **写入** — 先写成 `settings.json.tmp`，`write_all`、`sync_all`，再在进程级 `Mutex` 下重命名覆盖目标文件。任何失败路径都会删掉临时文件。
- **不可读、无法解析或非法文件** — 重命名为 `settings.json.bak-<unix 秒>`，内存中回落到默认值，手改坏的文件不会把页面卡死。备份保留原始字节。
- **保存校验** — 拒绝 0 和大于 65 535 的值，其余去重并升序排列，超过 50 条直接报错而不是截断。

前端也镜像了这些常量（`MAX_PINNED_PORTS = 50`、`DEFAULT_PINNED_PORTS = [3000, 5173, 8080, 5432, 27017]`），但以后端为准：每次保存和每次读取都会校验。

## 边界与平台说明

- **只处理 TCP 监听端口。** 不枚举 UDP，也只列监听中的套接字——出站连接的本端不算一行。
- **仅 Windows。** `scan`、`process`、`elevate` 都针对 Windows API 编译；其他目标返回带英文消息的 `internal`。既没有 macOS 的 `lsof` 路径，也没有 Linux 的 `/proc` 路径和 Flatpak 路径。
- **小于 1 000 的 PID 一律当作系统进程。** 恰好拿到低 PID 的用户进程会显示为 `system`，页面无法结束它。
- **端口可能显示为空闲，而 `netstat` 仍列着它。** Windows 可能为一个已经退出的 PID 保留 `LISTENING` 行；页面按自己的规则走（解析不出进程就是 `free`）。
- **3 秒窗口。** 在两次轮询之间出现又消失的端口不会被看到；刚结束的进程如果手动刷新与轮询竞争，可能要等一个间隔才从列表消失。
- 详情抽屉对 `system` 行和解析不出进程的行隐藏结束按钮；即使调用，`ports_kill` 也会拒绝同样的情形。

## 排障

| 现象 | 可能原因 |
| --- | --- |
| “not allowed by ACL” | 命令漏在 `build.rs` 或 `capabilities/default.json` 里 |
| 页面顶部出现加载错误行 | `ports_list` 失败——在开发者控制台看英文 `message` |
| 固定端口消失了 | 某个状态开关被关掉；筛选同样作用于固定端口列表 |
| 固定端口显示为空闲 | 当前没有服务监听它，这就是占位行 |
| 设置被重置为默认值 | `settings.json` 读不出或解析失败；找一下 `settings.json.bak-*` |
| “最多 50 个固定端口” | 上限就是 50，先删一个再加 |
| 结束进程连续两次提示无权限 | 提权的 `taskkill` 也失败了；看 `detail.exitCode` |
| 确认后只出现信息提示 | UAC 被取消，进程仍在运行 |
| 工具条显示已暂停 | 页面不活跃、窗口最小化，或文档隐藏 |
