# File Preview

The **文件预览** (File preview) family previews a file or browses a folder —
anything, whether or not it belongs to a project. It shows up in three places,
all of them the same viewer:

| Where | Route | Frame |
|-------|-------|-------|
| The **文件预览** page in the sidebar | `/file-preview` | The shared `AppShell`, with a project picker and the project file tree |
| The standalone preview window | `/preview-window` | Its own frameless window, hidden until the space agent hands it files |
| A preview tab in the **笔记** and **项目** editors | — | A codelet tab |

The engine is ported from [SpacePreview](https://github.com/likehao19/SpacePreview)
(MIT); see [UPSTREAM_PROJECTS.md](../UPSTREAM_PROJECTS.md) and the two
`UPSTREAM.md` records it links.

## How it works

```
page /file-preview ──┐
window /preview-window ─┤
editor preview tab    ─┘
        │
        ▼
components/space-preview/host.tsx        PreviewHost (embedded | window)
        └─ viewers/Preview.tsx ──▶ registry.detectKind ──▶ one viewer
              │                                   │
              │  lib/space-preview/bridge.ts      │  engine/*, worker/*
              ▼                                   ▼
        commands/services/space-preview      Web Worker (comlink)
              │                            parses DOCX, XLSX, archives…
              ▼
        space-preview-core (Rust)  ──▶  the file on disk
```

- **The backend only reads and writes bytes.** Every viewer parses in the
  webview, and the heavy ones run in a Web Worker so a large workbook does not
  freeze the UI. The Rust side is the crate
  [`src-tauri/space-preview-core`](../../src-tauri/space-preview-core).
- **One host, three frames.** The page, the window and the tabs all render
  `PreviewHost`; it owns loading, the toolbar, edit mode, saving and its
  encoding, so a file looks and behaves the same wherever it is opened.
- **Viewers are code-split.** `viewers/Preview.tsx` dispatches on the registry's
  kind and each engine is an `await import(...)`, so a window that never shows a
  spreadsheet never loads SheetJS.
- **The viewer CSS is scoped.** The upstream stylesheet is 78 KB of global
  selectors; every one is rewritten below `.sp-preview`, which the host's root
  element carries.

## Commands

The crate exposes 18 `sp_*` commands. They are mounted through the same four
hand-maintained lists as every other command — `src/invoke.rs`, `build.rs`,
`capabilities/default.json` and `permissions/autogenerated/*.toml`; see
[src-tauri/CLAUDE.md](../../src-tauri/CLAUDE.md).

| Command | Parameters | Returns |
|---------|------------|---------|
| `sp_inspect_file` | `path` | `PreviewFileInfo` — name, size, modified, mime, directory flag, etag. Admits the path. |
| `sp_list_directory` | `path`, `offset` | `DirectoryPage` — up to 500 entries and the next offset. Admits every entry it returns. |
| `sp_read_prefix` | `path`, `limit` | Raw bytes — for sniffing and lazy headers |
| `sp_read_range` | `path`, `offset`, `limit` | Raw bytes; at most 32 MiB per call |
| `sp_read_html_resource` | `path`, `base` | Raw bytes of an image, stylesheet or font next to an HTML file |
| `sp_write_text` | `path`, `text`, `encoding`, `etag?` | `WriteResult` — the new size, mtime and etag |
| `sp_probe_presentation` | — | `bool` — is PowerPoint available through COM |
| `sp_render_presentation` | `path` | `PreviewFileInfo` for the cached PDF |
| `sp_file_icon` | `path?`, `name`, `folder` | PNG bytes of the system icon |
| `sp_agent_status` | — | `AgentStatus` — enabled, running, COM ready |
| `sp_agent_set_enabled` | `enabled` | `AgentStatus` |
| `sp_hide_preview` | — | Hides the preview window and drops the pending hand-off |
| `sp_navigate_file_selection` | `current?`, `direction` | The file manager's next selected path, or `null` |
| `sp_cancel_file_navigation` | — | Abandons a navigation in flight |
| `sp_initial_paths` | — | `{ paths, text, fileManager }` — the hand-off a late window may have missed |
| `sp_open_preview` | `paths`, `text` | Opens the window on those paths |
| `sp_preferences_get` | — | `PreviewPreferences` |
| `sp_preferences_save` | `preferences` | `PreviewPreferences` |

### Authorization

There is no global read capability and no asset protocol.

- `sp_inspect_file` canonicalises the path and admits it to an in-memory
  allowlist. Only an admitted path can be read or written, and the list is
  cleared by a restart.
- `sp_list_directory` admits the directory, then admits each entry only after
  canonicalising it; an entry that resolves outside the listed directory — a
  symlink or junction pointing away — is skipped instead of admitted.
- `sp_read_html_resource` additionally confines the read to the HTML file's own
  directory and its subdirectories; `..` is refused.
- `sp_write_text` re-checks the etag and refuses when the file changed on disk
  after it was read.

The error contract is `{ code, message, detail? }` with kebab-case codes —
`not-authorized`, `not-found`, `too-large`, `invalid-input`, `unsupported`,
`internal`. The frontend maps the code to `spacePreview.error.*` and uses the
English `message` only as the fallback, via
[`viewers/errors.ts`](../../src/components/space-preview/viewers/errors.ts).

### Reading limits

| Limit | Value | Enforced by |
|-------|-------|-------------|
| One `read_range` call | 32 MiB | `io::MAX_READ` and the frontend bridge |
| A whole-file preview | 512 MiB by default, 16–2048 MiB preference | `limits.ts`, published from the preferences |
| One file inside an archive | 256 MiB by default, 16–1024 MiB preference | `archive-session.ts` and the archive viewer |
| An HTML resource | 32 MiB | `html::MAX_RESOURCE` |
| One directory page | 500 entries | `directory::PAGE_SIZE` |
| WMF / EMF | 16 MiB | the metafile viewer |
| TIFF | 32 MiB | the TIFF viewer |
| Highlighting a text / source file | 200,000 characters | `code-editor.tsx` (`MAX_HIGHLIGHT_CHARS`) |
| One page of a large text file | 1 KiB | `Preview.tsx` (`TEXT_PAGE_BYTES`) |
| Filling the text view before it waits for a scroll | 64 KiB | `code-editor.tsx` (`AUTO_FILL_CHARS`) |

A whole-file preview is assembled from ranges by
`engine/full-read.ts`, so a file at the limit is never held twice.

## The host

`PreviewHost` has two modes and one mental model: **a target in, a viewer out**.

- **Header** — the system icon, the file name, size and kind, then the toolbar.
- **Toolbar** — edit (only for text-like formats), reload, open in a window
  (embedded mode only), close (window mode only). A `‹` appears when an archive
  or a document opened a file inside itself; it goes back to the parent.
- **Edit mode** replaces the viewer with the bundled `CodeEditor`
  ([`src/components/code-editor.tsx`](../../src/components/code-editor.tsx)),
  plus Save, Cancel and an encoding selector.
- **States** — loading, the error (the command's code translated, the message as
  fallback), and an empty selection.
- **Preferences are live.** The settings window and the tray write the same
  `preview.json`; the host listens for `sp:preferences-changed`, and its own
  changes are written 400 ms after the last one, re-reading the file first so a
  concurrent tray toggle is not reverted.

## Folders

A folder is previewed by `viewers/DirectoryPreview.tsx`, which `Preview.tsx`
swaps in when `file.directory` is set.

- **The left pane is a lazy tree.** Expanding a folder calls `sp_list_directory`
  for that folder only — 500 entries per page, directories first, then names in
  a case-insensitive order. *Load more* asks for the next page; nothing reads a
  subtree ahead of the click and no tree is cached between folders.
- **The right pane is the same viewer.** Picking a file renders `Preview` for
  it, so every format, the text view and the toolbar behave as they do
  everywhere else. A viewer that opens a file from inside its own format (an
  archive entry, a mail attachment) stacks on top, and the header's `‹` returns
  to the parent file.
- **Icons come from Windows.** Each row draws the system icon through the same
  cached `sp_file_icon` request the rest of the viewer uses.
- **The sidebar resizes.** Drag the divider, or focus it and use the arrow keys,
  Home and End; the width is local state clamped to 150–640 px and to 55% of the
  pane, and is not persisted.
- **A failed listing stays on screen.** The branch shows a translated error with
  *Retry*; an empty folder says so instead.
- **The tree cannot escape its root.** An entry that canonicalises outside the
  folder it was listed from — a symlink or junction pointing away — is never
  returned by `sp_list_directory`.

## The text view

Text and source files have two read-only renderings, chosen by the file size
against the **text file threshold** preference (default 500 KB):

- **Below the threshold — the foldable line view.** One element per line with
  line numbers, plus fold controls for JSON and XML. Lines are highlighted one
  at a time with the app's own grammars
  ([`src/lib/git-core/highlight.ts`](../../src/lib/git-core/highlight.ts)),
  carrying block comments across lines, and the colours are the theme's global
  `.hljs-*` map rather than the ported viewers' fixed palette.
- **Above it — the editor view, read only.** `CodeEditor` paints the text as one
  highlighted block over the input layer instead of one element per line, so a
  long file costs two nodes rather than tens of thousands. Past the
  200,000-character cap the highlight pass is skipped and the input layer shows
  the text itself, which keeps a huge file from being escaped and repainted on
  every appended page. Above 2 MB the file is not read in one piece: the first
  1 KB is shown and the next page is appended as the reader scrolls to the end,
  decoded by one streaming `TextDecoder` so a character is never split across
  the boundary. The view fills itself until the text is taller than the pane, so
  a short file is readable without touching the wheel.

Both show the detected encoding and the line count in the toolbar and offer the
same encoding list as the editor. They are read only: the host's pencil swaps in
the editable `CodeEditor`, and starting an edit still reads the whole file — so
a file above the threshold has no pencil at all. The question mark beside the
threshold in **Settings → File preview** says so.

## Editing

Text-like files can be edited in place; every structured format is read-only.

- The pencil appears for the engines `text`, `markdown`, `csv` and `asciidoc`.
  It reads through the same allowlisted path — not through the project writer —
  so outside a project the file is still editable.
- **Editing stops at the text-file threshold.** An edit reads the whole file into
  the editor, so a larger file has no pencil and is preview-only.
- **Saves are compare-and-set.** `sp_write_text` carries the etag from the
  `sp_inspect_file` that loaded the file and refuses the write when the file
  changed meanwhile; the toast shows the reason and the text stays in the
  editor.
- **The encoding is a first-class choice.** `auto` decodes with the detector's
  answer (UTF-8, UTF-16 LE/BE, GB18030), the selector offers UTF-8, UTF-16
  LE/BE, GB18030, Big5, Windows-1252 and Shift-JIS, and the save writes back in
  the encoding that is selected — so a GB18030 file stays GB18030 instead of
  becoming UTF-8. CRLF line endings are preserved. The *default* encoding for
  the next file is a preference, not a per-file guess.
- **Ctrl/Cmd+S** saves, **Tab** inserts two spaces, and the editor's find bar is
  codelet's own. Picking another file or project, leaving edit mode, or closing
  the window while the text is dirty asks first.
- Highlighting follows the file name through
  `src/lib/git-core/highlight.ts`; an unknown extension is plain text.

## The standalone window

`/preview-window` is declared hidden and frameless in
`src-tauri/tauri.conf.json` and shown by the space agent. It is a singleton:
closing hides it, it is never destroyed.

- The agent sends `sp:preview-files` with the selected paths; the window turns
  them into entries through `sp_inspect_file` and shows the first. A window that
  mounted after the hand-off asks `sp_initial_paths`.
- **Arrow keys** move through the selection (`ArrowUp`/`ArrowLeft` back,
  `ArrowDown`/`ArrowRight` forward). The move asks the file manager through
  `sp_navigate_file_selection` first, so the window follows the real Explorer /
  desktop / Everything selection; when that fails it steps through the list it
  was handed, wrapping at the ends.
- **File tabs** appear when the *Use file tabs* preference is on and the
  hand-off has more than one file. Each tab can be closed; closing the active
  one hands the viewer to its right neighbour, or to the left when it was last,
  and closing the last one hides the window. Switching tabs, closing a tab or
  dropping a file over unsaved edits asks first. With tabs off the window shows
  one file at a time and the arrow keys remain the way through the selection.
- **Space and Escape close** — unless the focus is in a field, a selector or a
  contenteditable element, in which case the keystroke belongs to it. An
  unsaved edit asks before the window hides.
- **Drag and drop** opens the first dropped file or folder; an unreadable path
  is skipped.
- **Folders open too.** A hand-off or a drop that is a folder shows the
  directory viewer described above.

### The space agent

- A low-level keyboard hook (`SetWindowsHookExW(WH_KEYBOARD_LL)`) watches the
  configured preview key — Space by default, or Win + Space from
  **设置 → 快捷键 → 文件预览** — only while the foreground window is Explorer,
  the desktop or Everything **and** a file list has focus. In an address bar, a
  search field or a rename box the key is passed through untouched. Holding
  Shift opens a text-like file as plain text.
- The selection itself comes from Shell COM on a dedicated STA thread;
  Everything's results are read from its own list.
- The handler is **on by default**. The settings switch and the tray's
  **Space Preview** item both call `sp_agent_set_enabled`, which retunes the
  hook immediately — no restart — and the state is kept in `preview.json`.
  There is no autostart registration.
- `sp_agent_status` reports `enabled`, `running` and `comReady`; the settings
  row shows *Running*, *Off* or *Enabled, not running*.

## Preferences

`<data dir>/preview.json`, written atomically by `prefs.rs` (`.tmp` →
`sync_all` → rename; a corrupt file is moved aside and the defaults are used).
The defaults are:

```json
{
  "version": 1,
  "spaceEnabled": true,
  "readingWidth": 900,
  "fontSize": 15,
  "defaultEncoding": "auto",
  "textPreviewThresholdKb": 500,
  "font": "auto",
  "wrap": true,
  "html": "source",
  "maxPreviewMiB": 512,
  "maxArchiveEntryMiB": 256,
  "tabs": false,
  "previewKey": "space"
}
```

`src/lib/space-preview/preferences.ts` resets anything a damaged file or an
older build left behind to its default. **设置 → 文件预览设置** is one page of
five tabs — **预览 / 资源与性能 / 多文件预览 / 快捷键 / 使用指南** — under a
fixed space switch that stays visible on every tab. It edits every value and
saves automatically; the reading width and font size are also adjustable in the
viewer's own reading-width control, which writes the same file. The preview key
lives in **设置 → 快捷键 → 文件预览** (Space or Win + Space) and
retunes the running agent without a restart. A file written before a field
existed reads that field's default instead of being discarded.

## Editor preview tabs

The same host is registered as a codelet custom editor
([`src/lib/editor/preview-extension.ts`](../../src/lib/editor/preview-extension.ts)).

- Only the formats text editing is worse at are claimed. Everything listed in
  the extension's `TEXT_EXTENSIONS` (Markdown, JSON, source, `csv`, `tsv`, HTML,
  SVG) keeps its text tab, and the text, markdown and CSV engines are excluded
  entirely.
- The selector is one generated `**/*.{…}` alternation built from the registry,
  so adding an engine also claims it here — there is no second list to keep in
  step.
- The provider itself draws nothing; it forwards the opened path and the host
  renders the viewer over the workbench, exactly as the page does.

## Build assets

`scripts/prepare-preview.mjs` runs before both `vite dev` and `vite build`
(`predev` / `prebuild`) and copies what cannot live in the JS bundle:

- `public/engines/libarchive.wasm`, `sql-wasm.wasm`
- `public/engines/archive-worker.js`, the libarchive worker with its
  swallow-read-errors bug patched so a corrupt archive reports a failure instead
  of an empty directory
- `public/pdfjs/{cmaps,standard_fonts,wasm,iccs}`

## Limits

- **Text-like files are editable; structured formats are not.** A document,
  spreadsheet, image or archive viewer has no editor.
- **Large text switches to the read-only editor view.** Above the text-file
  threshold the foldable line view gives way to `CodeEditor` — no line numbers,
  but the find bar stays — and above 200,000 characters the highlight pass is
  skipped as well, so a large log renders uncoloured rather than being split into
  an element per line. Past 2 MB the view reads 1 KB pages as the reader scrolls
  instead of the whole file.
- **A file above the threshold cannot be edited.** The pencil is hidden; editing
  would have to read the whole file into the editor.
- **The whole-file preview cap is a preference (512 MiB by default).** Larger
  files are listed but not read; the pane says so instead of loading them, and
  the backend's per-range cap makes a direct call unable to sidestep it. The
  archive inner-file cap (256 MiB by default) works the same way for one file
  extracted from an archive.
- **PDF pages render on demand.** Search, the outline and the text layer come
  from pdf.js; a damaged or password-protected PDF says which.
- **PowerPoint needs PowerPoint for the best result.** With Office installed the
  slides are converted to a cached PDF through COM; without it the built-in
  `pptxviewjs` renderer shows a text overview.
- **Light "paper" colours on purpose.** Viewer content keeps them in dark mode
  too — a document should look like a document. The surrounding chrome follows
  the theme.
- **Windows is the verified platform.** The space agent, PowerPoint conversion
  and system icons are Windows-only; the viewers themselves are portable and the
  non-Windows branches compile to empty stubs.

## Adding a format

1. Write the engine under `src/lib/space-preview/engine/` (keep it on a dynamic
   `import()`; put heavy parsing in `worker/`).
2. Add a viewer under `src/components/space-preview/viewers/` and dispatch to it
   from `viewers/Preview.tsx`.
3. Add the descriptor to `engines` in `registry.ts`. That single row feeds
   `detectKind`, the mime guess, the editor tab's selector and the tests.
4. If it needs a new dependency, add it to `package.json`; if it needs a wasm
   module or data directory, copy it in `scripts/prepare-preview.mjs`.
5. Add the cases to `src/lib/space-preview/__tests__/registry.test.ts` and a pure
   function test for the parser.

Ported files under `src/lib/space-preview/{engine,worker}`,
`src/components/space-preview/viewers` and `space-preview.css` keep their
upstream style and are listed in `.prettierignore`; host-owned files beside them
are formatted as usual.
