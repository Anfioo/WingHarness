# AI 配置同步

**AI 配置同步**页面正在构建中。侧栏入口与 `/ai-config` 路由保留，但引擎重建
期间页面只显示「构建中」提示。

## 当前状态

引擎位于 [`src-tauri/agent-sync-core`](../../src-tauri/agent-sync-core)，只是
一个普通的 workspace 成员：

- 不暴露 Tauri 命令，因此不出现在 `invoke.rs`、`build.rs`、
  `capabilities/default.json` 与 `permissions/autogenerated/` 中；
- 没有其他 crate 依赖它——根 `Cargo.toml` 不再把它列为依赖；
- 前端没有命令包装，也不会调用它。

它仍然参与编译，自身的测试仍然可以运行：

```bash
cargo check --workspace
cargo test -p agent-sync-core
```

## 配置

`config.json` 不再有 `aiConfig` 字段。结构体保留 `serde(default)`，且没有
`deny_unknown_fields`，所以旧文件里残留的 `aiConfig` 键会被正常忽略，而不是
导致读取失败。这一点有回归测试覆盖。

## 来源

该 crate 派生自 [shaic](https://github.com/dariocurr/shaic) v0.3.0 的 `core/`
crate（MIT）。目前它的 store / adapter / materialise 逻辑保持不变，移走的只是
应用侧集成。MIT 声明与上游许可证文本仍然保留，移植记录见
`agent-sync-core/UPSTREAM.md`。

## 方向

该模块将以 skill 优先的资产仓库形式回归：skill 是主要管理的资产，store 与
adapter 会围绕这一模型裁剪和改造，之后页面才会恢复。在那之前，不要为这个 crate
添加命令、权限或前端包装——下一步从引擎本身开始。
