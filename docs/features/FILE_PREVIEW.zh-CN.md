# 文件预览

**文件预览** 这一组页面用来预览文件或浏览文件夹——任何内容，不论它是否属于某个
项目。它以三个入口出现，用的都是同一个查看器：

| 位置 | 路由 | 外壳 |
|------|------|------|
| 侧栏的 **文件预览** 页 | `/file-preview` | 共享的 `AppShell`，带项目选择器和项目文件树 |
| 独立预览窗口 | `/preview-window` | 自己的无边框窗口，在空格代理交付文件之前保持隐藏 |
| **笔记** 与 **项目** 编辑器里的预览页签 | — | 一个 codelet 页签 |

引擎移植自 [SpacePreview](https://github.com/likehao19/SpacePreview)（MIT）；见
[UPSTREAM_PROJECTS.md](../UPSTREAM_PROJECTS.md) 以及它链接的两份 `UPSTREAM.md`
记录。

## 工作原理

```
页面 /file-preview ──┐
窗口 /preview-window ─┤
编辑器预览页签        ─┘
        │
        ▼
components/space-preview/host.tsx         PreviewHost（embedded | window）
        └─ viewers/Preview.tsx ──▶ registry.detectKind ──▶ 一个查看器
              │                                   │
              │  lib/space-preview/bridge.ts      │  engine/*、worker/*
              ▼                                   ▼
        commands/services/space-preview      Web Worker（comlink）
              │                            解析 DOCX、XLSX、归档…
              ▼
        space-preview-core（Rust）  ──▶  磁盘上的文件
```

- **后端只负责读写字节。** 所有解析都在 webview 里完成，重活放在 Web Worker，
  所以打开一个很大的工作簿也不会卡住界面。Rust 一侧是
  [`src-tauri/space-preview-core`](../../src-tauri/space-preview-core) crate。
- **一个宿主，三种外壳。** 页面、窗口和页签都渲染 `PreviewHost`；加载、工具栏、
  编辑模式、保存和编码都由它负责，所以同一个文件在哪里打开都长得一样、行为一样。
- **查看器按需拆分。** `viewers/Preview.tsx` 按注册表的 kind 分发，每个引擎都是
  `await import(...)`，从不显示表格的窗口也就从不加载 SheetJS。
- **查看器样式是作用域化的。** 上游样式表有 78 KB 的全局选择器，全部改写到
  `.sp-preview` 之下，宿主根元素带着这个 class。

## 命令

该 crate 暴露 18 个 `sp_*` 命令。它们和其余命令一样，要通过四份手工维护的清单
挂载——`src/invoke.rs`、`build.rs`、`capabilities/default.json` 与
`permissions/autogenerated/*.toml`；见
[src-tauri/CLAUDE.md](../../src-tauri/CLAUDE.md)。

| 命令 | 参数 | 返回 |
|------|------|------|
| `sp_inspect_file` | `path` | `PreviewFileInfo`——名称、大小、修改时间、mime、是否目录、etag。同时把路径加入白名单。 |
| `sp_list_directory` | `path`、`offset` | `DirectoryPage`——最多 500 个条目与下一页的偏移量。返回的每个条目都会加入白名单。 |
| `sp_read_prefix` | `path`、`limit` | 原始字节——用于嗅探与懒加载文件头 |
| `sp_read_range` | `path`、`offset`、`limit` | 原始字节；单次最多 32 MiB |
| `sp_read_html_resource` | `path`、`base` | HTML 文件旁边的图片、样式表或字体的原始字节 |
| `sp_write_text` | `path`、`text`、`encoding`、`etag?` | `WriteResult`——新的大小、修改时间与 etag |
| `sp_probe_presentation` | — | `bool`——能否通过 COM 使用 PowerPoint |
| `sp_render_presentation` | `path` | 缓存 PDF 的 `PreviewFileInfo` |
| `sp_file_icon` | `path?`、`name`、`folder` | 系统图标的 PNG 字节 |
| `sp_agent_status` | — | `AgentStatus`——已启用、运行中、COM 就绪 |
| `sp_agent_set_enabled` | `enabled` | `AgentStatus` |
| `sp_hide_preview` | — | 隐藏预览窗口并丢弃待处理的交付 |
| `sp_navigate_file_selection` | `current?`、`direction` | 文件管理器选中的下一个路径，或 `null` |
| `sp_cancel_file_navigation` | — | 放弃进行中的导航 |
| `sp_initial_paths` | — | `{ paths, text, fileManager }`——晚挂载的窗口可能错过的交付 |
| `sp_open_preview` | `paths`、`text` | 在这些路径上打开预览窗口 |
| `sp_preferences_get` | — | `PreviewPreferences` |
| `sp_preferences_save` | `preferences` | `PreviewPreferences` |

### 授权

这里没有全局读取能力，也不启用 asset protocol。

- `sp_inspect_file` 规范化路径并把它加入内存白名单。只有被放行的路径才能被读写，
  重启即清空。
- `sp_list_directory` 先放行目录，再逐个规范化条目后才放行；指向目录之外的符号
  链接或目录联接会被跳过，而不是被放行。
- `sp_read_html_resource` 额外把读取限制在 HTML 文件所在目录及其子目录内；`..`
  会被拒绝。
- `sp_write_text` 会重新核对 etag；文件在读取之后被改动过就拒绝写入。

错误契约是 `{ code, message, detail? }`，code 为 kebab-case——`not-authorized`、
`not-found`、`too-large`、`invalid-input`、`unsupported`、`internal`。前端用
code 映射到 `spacePreview.error.*`，英文 `message` 只作兜底，见
[`viewers/errors.ts`](../../src/components/space-preview/viewers/errors.ts)。

### 读取上限

| 上限 | 值 | 执行方 |
|------|----|--------|
| 单次 `read_range` | 32 MiB | `io::MAX_READ` 与前端数据桥 |
| 整文件预览 | 默认 512 MiB，可在 16–2048 MiB 间设置 | `limits.ts`，由偏好发布 |
| 压缩包内的单个文件 | 默认 256 MiB，可在 16–1024 MiB 间设置 | `archive-session.ts` 与归档查看器 |
| 单个 HTML 资源 | 32 MiB | `html::MAX_RESOURCE` |
| 单页目录 | 500 个条目 | `directory::PAGE_SIZE` |
| WMF / EMF | 16 MiB | 图元查看器 |
| TIFF | 32 MiB | TIFF 查看器 |
| 文本 / 源码高亮 | 200,000 字符 | `code-editor.tsx`（`MAX_HIGHLIGHT_CHARS`） |
| 大文本预览的一页 | 1 KiB | `Preview.tsx`（`TEXT_PAGE_BYTES`） |
| 文本视图等待滚动前的自动填充 | 64 KiB | `code-editor.tsx`（`AUTO_FILL_CHARS`） |

整文件预览由 `engine/full-read.ts` 拼接分段读取，所以达到上限的文件也不会在内存
里存在两份。

## 宿主

`PreviewHost` 有两种模式，但只有一个心智模型：**进一个目标，出一个查看器**。

- **头部**——系统图标、文件名、大小与类型，其后是工具栏。
- **工具栏**——编辑（仅限文本类格式）、重新加载、在独立窗口打开（仅嵌入模式）、
  关闭（仅窗口模式）。归档或文档打开了自身内部的某个文件时，会出现 `‹`，返回
  上层文件。
- **编辑模式**把查看器换成内置的 `CodeEditor`
  （[`src/components/code-editor.tsx`](../../src/components/code-editor.tsx)），
  并附保存、取消和编码选择器。
- **各种状态**——加载中；错误（命令的 code 译成文案，message 作兜底）；以及空选择。
- **偏好是实时的。** 设置窗口与托盘写同一个 `preview.json`；宿主监听
  `sp:preferences-changed`，自己的改动在最后一次变更 400 ms 后写入，写前先重读
  文件，以免把托盘并发切换的开关覆盖回去。

## 文件夹

文件夹由 `viewers/DirectoryPreview.tsx` 预览，`Preview.tsx` 在 `file.directory`
为真时换用它。

- **左栏是懒加载的目录树。** 展开一个文件夹只会为它调用一次 `sp_list_directory`
  ——每页 500 个条目，目录在前，随后按名称不区分大小写排序。*加载更多* 会取下一页；
  点击之前不会预先读取任何子树，文件夹之间也不缓存整棵树。
- **右栏是同一个查看器。** 选中文件就用 `Preview` 渲染它，所以每种格式、文本视图
  和工具栏都与别处行为一致。如果查看器从自身格式内部打开文件（归档条目、邮件附件），
  会叠加在上层，头部 `‹` 返回父文件。
- **图标来自 Windows。** 每一行都通过查看器其余部分共用的缓存 `sp_file_icon`
  请求绘制系统图标。
- **侧栏可调整宽度。** 拖动分隔条，或聚焦后使用方向键、Home 与 End；宽度是本地
  状态，限制在 150–640 px 且不超过面板的 55%，不做持久化。
- **读取失败会留在原地。** 该分支显示译好的错误与 *重试*；空文件夹则直接说明为空。
- **目录树走不出根目录。** 规范化后落在所列文件夹之外的条目——指向外部的符号链接
  或目录联接——`sp_list_directory` 根本不会返回。

## 编辑

文本类文件可以就地编辑；所有结构化格式都是只读的。

- 铅笔只在 `text`、`markdown`、`csv`、`asciidoc` 四种引擎下出现。它读的是同一条
  白名单路径——不是项目写入器——所以在项目之外也能编辑。
- **编辑在文本文件阈值处止步。** 编辑要把整个文件读进编辑器，所以更大的文件不显示铅笔，
  只能预览。
- **保存是比较后写入。** `sp_write_text` 带着加载文件时 `sp_inspect_file` 给出的
  etag，文件在此期间被改动就拒绝写入；toast 说明原因，文本留在编辑器里。
- **编码是一等选择。** `auto` 使用探测结果（UTF-8、UTF-16 LE/BE、GB18030），
  选择器提供 UTF-8、UTF-16 LE/BE、GB18030、Big5、Windows-1252 与 Shift-JIS，
  保存时按所选编码写回——GB18030 文件仍是 GB18030，不会变成 UTF-8。CRLF 换行
  保留。下个文件使用的*默认*编码是一项偏好，而不是对单个文件的猜测。
- **Ctrl/Cmd+S** 保存，**Tab** 插入两个空格，查找栏是 codelet 自带的。文本有未
  保存改动时，切换文件或项目、退出编辑模式、关闭窗口都会先询问。
- 高亮按文件名选择语法，走 `src/lib/git-core/highlight.ts`；未知扩展名按纯文本
  处理。

## 文本视图

文本与源码文件有两种只读渲染，由文件大小和**文本文件阈值**偏好（默认 500 KB）决定：

- **低于阈值——可折叠的行视图。** 每行一个元素，带行号；JSON 与 XML 还有折叠控件。
  每行单独高亮，语法来自本应用自己的
  [`src/lib/git-core/highlight.ts`](../../src/lib/git-core/highlight.ts)，会跨行延续
  块注释，颜色使用主题的全局 `.hljs-*`，而不是移植查看器那套固定配色。
- **超过阈值——只读的编辑器视图。** `CodeEditor` 把整篇文本画成输入层之上的一个高亮块，
  不再每行一个元素，所以长文件只占两个节点而不是几万个。超过 200,000 字符的上限时连
  高亮也跳过，由输入层直接显示文本本身，这样超大文件不会在每次追加一页时被转义重绘。
  超过 2 MB 时不再整文件读入：先显示前 1 KB，向下滚动到末尾时追加下一页，由同一个流式
  `TextDecoder` 解码，字符不会被切在分页边界上。视图会自动加载到文字高于面板为止，
  所以短文件不必滚动也能读完。

两种视图的工具栏都显示探测到的编码与行数，并提供与编辑器相同的编码列表。它们都是只读
的：宿主上的铅笔会换成可编辑的 `CodeEditor`，开始编辑时仍然整文件读取——因此超过阈值的
文件不显示铅笔。**设置 → 文件预览** 中阈值旁的问号说明了这一点。

## 独立窗口

`/preview-window` 在 `src-tauri/tauri.conf.json` 中声明为隐藏、无边框，由空格
代理显示。它是单例：关闭只是隐藏，从不销毁。

- 代理发送 `sp:preview-files`，带上选中的路径；窗口通过 `sp_inspect_file` 把它们
  变成条目，并显示第一个。晚挂载的窗口会调用 `sp_initial_paths` 取回错过的交付。
- **方向键**在选中项之间移动（`ArrowUp`/`ArrowLeft` 后退，`ArrowDown`/
  `ArrowRight` 前进）。移动先通过 `sp_navigate_file_selection` 询问文件管理器，
  所以窗口跟随真实的 Explorer / 桌面 / Everything 选中项；询问失败时在收到的列表
  里循环前后移动。
- **文件标签页**在打开「使用文件标签页」偏好且交付了多个文件时出现。每个标签页都能
  关闭；关闭当前页时交给右侧邻居，是最后一页则交给左侧，关闭唯一一页时隐藏窗口。
  切换标签页、关闭标签页或在有未保存编辑时拖入文件都会先询问。关闭标签页后，窗口
  一次只显示一个文件，方向键仍是在选中项中穿行的方法。
- **空格与 Esc 关闭**——但如果焦点在输入框、选择器或 contenteditable 元素里，按键
  归属于它。有未保存的编辑时，窗口隐藏前会先询问。
- **拖放**打开第一个拖入的文件或文件夹；不可读的路径被跳过。
- **文件夹也能打开。** 交付或拖入的是文件夹时，显示上文所述的目录查看器。

### 空格代理

- 低级键盘钩子（`SetWindowsHookExW(WH_KEYBOARD_LL)`）只在**前台是 Explorer、桌面
  或 Everything，且文件列表有焦点**时监听配置的预览快捷键——默认是空格，也可以在
  **设置 → 快捷键 → 文件预览** 中改为 Win + 空格。在地址栏、搜索框或
  重命名框里，按键原样放行。按住 Shift 会把文本类文件按纯文本打开。
- 选中项本身由独立 STA 线程上的 Shell COM 读取；Everything 的结果从其自身列表
  读取。
- 处理器**默认开启**。设置开关与托盘里的 **Space Preview** 项都调用
  `sp_agent_set_enabled`，立即重新调整钩子——无需重启——状态保存在
  `preview.json`。不注册开机自启。
- `sp_agent_status` 返回 `enabled`、`running` 与 `comReady`；设置行显示
  *Running*、*Off* 或 *Enabled, not running*。

## 偏好

`<数据目录>/preview.json`，由 `prefs.rs` 原子写入（`.tmp` → `sync_all` →
rename；损坏的文件被移开并使用默认值）。默认值：

```json
{
  "version": 1,
  "spaceEnabled": true,
  "readingWidth": 900,
  "fontSize": 15,
  "defaultEncoding": "auto",
  "textPreviewThresholdKb": 500,
  "font": "auto",
  "wrap": true,
  "html": "source",
  "maxPreviewMiB": 512,
  "maxArchiveEntryMiB": 256,
  "tabs": false,
  "previewKey": "space"
}
```

`src/lib/space-preview/preferences.ts` 会把损坏文件或旧版本留下的值重置为默认值。
**设置 → 文件预览** 是一个页面，固定显示空格预览开关，下面分
**预览 / 资源与性能 / 多文件预览 / 快捷键 / 使用指南** 五个标签页；它编辑全部取值
并自动保存，阅读宽度与字号也可以在查看器自己的阅读宽度控件里调整，写入同一个文件。
预览快捷键在 **设置 → 快捷键 → 文件预览** 中设置（空格或 Win + 空格），
并立即重新调整运行中的代理，无需重启。某个字段出现之前写下的文件会按该字段的默认值
读取，而不是被丢弃。

## 编辑器预览页签

同一个宿主注册为 codelet 自定义编辑器
（[`src/lib/editor/preview-extension.ts`](../../src/lib/editor/preview-extension.ts)）。

- 只接管文本编辑更不擅长的格式。扩展名自己的 `TEXT_EXTENSIONS`（Markdown、JSON、
  源代码、`csv`、`tsv`、HTML、SVG）保留文本页签，text、markdown 与 CSV 三种引擎
  完全不接管。
- 选择器是由注册表生成的一条 `**/*.{…}` 交替式 glob，所以在注册表里加一个引擎，
  这里也会自动接管——没有第二份清单要同步。
- 提供者本身什么都不画；它只转发打开的路径，宿主把查看器铺在工作台之上，和页面里
  完全一样。

## 限制

- **文本类文件可编辑，结构化格式不可。** 文档、表格、图片或归档查看器没有编辑器。
- **大文本切换成只读的编辑器视图。** 超过文本文件阈值后可折叠的行视图让位给
  `CodeEditor`（没有行号，但保留查找栏）；超过 200,000 字符时连高亮也跳过，所以大型
  日志按无色文本渲染，而不是被拆成每行一个元素。超过 2 MB 时随滚动按 1 KB 一页读取，
  而不是整文件读入。
- **超过阈值的文件不能编辑。** 铅笔被隐藏；编辑必须把整个文件读进编辑器。
- **整文件预览上限是一项偏好（默认 512 MiB）。** 更大的文件仍会列出但不会读取；
  面板会说明原因，而后端的单次分段上限让直接调用也无法绕过。压缩包内单个文件的上限
  （默认 256 MiB）对从归档中解压出来的文件同理。
- **PDF 逐页按需渲染。** 搜索、大纲与文本层来自 pdf.js；损坏或加密的 PDF 会说明
  具体原因。
- **PowerPoint 需要 PowerPoint 才能得到最佳效果。** 装了 Office 时通过 COM 把
  幻灯片转成缓存 PDF；没有时由内置的 `pptxviewjs` 渲染器给出文本概览。
- **浅色“纸张”配色是刻意的。** 暗色模式下查看器内容也保持浅色——文档就该像文档。
  周围的外壳跟随主题。
- **只验收 Windows。** 空格代理、PowerPoint 转换与系统图标是 Windows 专属；查看器
  本身可移植，非 Windows 分支编译为空桩。

## 新增一种格式

1. 在 `src/lib/space-preview/engine/` 下写引擎（保持动态 `import()`；重解析放进
   `worker/`）。
2. 在 `src/components/space-preview/viewers/` 下写查看器，并在
   `viewers/Preview.tsx` 里分发。
3. 在 `registry.ts` 的 `engines` 加一条描述。这一行同时喂给 `detectKind`、mime
   猜测、编辑器页签的选择器与测试。
4. 需要新依赖就加进 `package.json`；需要 wasm 模块或数据目录就在
   `scripts/prepare-preview.mjs` 里复制。
5. 在 `src/lib/space-preview/__tests__/registry.test.ts` 补用例，并为解析器补一个
   纯函数测试。

`src/lib/space-preview/{engine,worker}`、`src/components/space-preview/viewers` 与
`space-preview.css` 下的移植文件保留上游格式，已列入 `.prettierignore`；旁边的宿主
自有文件照常格式化。
